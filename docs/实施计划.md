## 1. 一句话定位

把 `E:\Trace_NL`（需求文档追溯）与 `E:\SAMA-V1`（图纸解析与追溯）**降格为两个域适配器**，
在其上抽出统一内核 `TraceGraph`，新增跨域锚定与测试用例生成两项能力，
最终封装为**单智能体 + 22 个 MCP 工具**，交付一个可现场演示、结论可审计的 V&V 智能体。

**整合方式：绞杀者模式。** 两个原工程的业务代码一行不重写，只加 `service.py` 包壳。
P0 已用行为等价性证明（§5.2）确认这条路线是安全的。

## 3. 贯穿全程的三条公理与四条原则

**三条公理（不可动摇）**
1. **一切皆追溯边** —— `TraceEdge` 是唯一的关系载体，不存在第二套异构结构。
2. **证据必须可定位** —— 每条边至少一条 `Evidence`，且携带 `Locator`（可点击跳转）。A2 已在 P0 落为**代码事实**：`TraceGraph.add_edge(strict=True)` 硬拒绝无证据边。
3. **判定链必须确定性** —— 数值/步骤/结论只由算法产生；LLM 仅出现在三个点位（歧义裁决、语义成文、任务分流），且 `llm_opinion` 独立成字段，**永不回写 `confidence`**。

**四条工程原则**
规则优先（可符号化求解的绝不交 LLM）· 证据随行 · 留人在环 · 工具标准化（全部经 MCP 暴露）。

## 4. ⚠ P2 路线修正（依据 P0 实测）

### 4.1 原计划的桥接假定

架构方案 §5.1 假定：**位号（Tag）是把"文"与"图"缝在一起的唯一现实锚点**，
并以"位号重合率 ≥ 30% 触发门控加法"作为融合规则的核心。

### 4.2 P0 实测结果（`eval/r1_tag_alignment.py`）

在真实的 9 页 SAMA 图纸 IR 与 5 份真实文档（合计 30 页）上：

| 锚点 | 命中率 | 结论 |
|---|---|---|
| **A1 位号**（MP101 / 401XU1…） | **0 / 66 = 0.0%** | ❌ 不成立 |
| A2 图名/系统号/图号 | 0 / 12 = 0.0% | ❌ 不成立 |
| **A2b 系统代号/中文系统名** | **3 / 10 = 30.0%** | ✅ **可行**（命中 CAM / TSA / TSM） |
| A3 回路号/跨页引用 | 1 / 66 = 1.5% | ❌ 不成立 |
| **A4 功能叙述关键词** | **3 / 13 = 23.1%** | ✅ **可行**（命中 BUP / DAS / 蒸汽管道隔离） |

**根因（已查实，非提取故障）**：文档文本层完好（无 OCR 需求），但需求/设计文档处于
**功能与系统抽象层**——它们引用标准号（HAD102、GB/T12727、IEEE1012）、需求条目号
（SYRS001–014、ICADS001–…）与系统名（"CAM 安全壳大气监测系统"），
**不引用仪表位号**。位号存在于 IO 清单与定值手册，那是**图纸域内部与知识层**的词汇。

### 4.3 修正后的 P2 设计

```
原设计：base = 0.45×语义 + 0.25×位号 + 0.15×图号/回路号 + 0.15×结构
        位号重合率 ≥0.30 → score += 0.50×位号重合率     ← 主锚点失效

修正为：base = 0.45×功能语义 + 0.30×系统代号/缩略语 + 0.15×图号/回路号命中 + 0.10×结构一致性
        系统代号命中（CAM/TSA/TSM 级，门控 ≥0.30）→ score += 0.40
        位号锚点降级为「图纸域内部与 IO/定值知识层专用」
```

| 变化 | 内容 |
|---|---|
| **主锚点** | A1 位号 → **A2b 系统代号 + A4 功能语义** |
| **位号的新角色** | 仅用于：图纸域内部归因、用例判据绑定定值与 IO、不与需求文档做锚定 |
| **A4 的复用价值上升** | 把 IR 回路折叠成功能叙述（`struct_narrate`）后走 Trace_NL 的嵌入 + NLI + 判定树——这条路线**从"辅助"升为"主力"** |
| **演示话术必须修正** | 不可承诺"点需求条目高亮图纸回路"这类位号级精确联动；应表述为"系统级/功能级关联 + 置信度与证据可见"，并**诚实标注语义路线置信度低于确定性锚点** |
| **风险状态** | R1 由「未验证/致命」→「已验证，影响可控」；代价是桥接精度预期下调 |

### 4.4 必须补做的一次复测（P2 启动前置）

现有语料中 `系统需求/DCS需求说明书.pdf` **仅为第 8 页起的 15 页摘录（文档自述共 90 页）**，
且**缺失 SAMA/FD 设计图本身**（只有 1 份组态样图 `安全壳SAMA.pdf`）。
因此上述比率**系统性偏低，不可外推为真实工程结论**。

> **P2 启动条件（Gate）**：取得完整版《系统设计说明书》+ 含追踪附录表的《系统需求》+
> 与图纸同项目的 SAMA/FD 设计图后，**重跑 R1 复测**。
> 若复测 A1 位号命中率 ≥ 30%，则恢复位号主锚点（成本更低、可解释性更强）；
> 若仍 < 30%，按 §4.3 修正路线执行，并在评测报告中并列呈现两次结果。

#### P1 关键设计决策：单编排器 + 工具作用域（不是"一个执行体挂 22 个工具"）

方案原文（docx）写"四个专业子智能体"，架构方案写"单智能体 + 工具集"。二者说的是**两件不同的事**，
本阶段按如下方式统一：

| 概念 | 选择 |
|---|---|
| 运行时形态（进程 / LLM 上下文 / 留痕） | **一个**（可审计、可复现） |
| 角色与权限域（谁能调什么工具、谁能碰 LLM） | **四个**（硬约束） |

理由：**22 个工具对"选工具"不构成负载**——标准路径由剧本查表 + 确定性 Router 选工具，**不经 LLM**；
真正的风险是**确定性边界失守**：方案要求图纸理解与校验复核两个角色"不可调用大模型"，
若合并为单一执行体，该约束只能写在提示词里，而提示词约束不是工程约束。

| 作用域 | 工具数 | LLM 权限 | 理由 |
|---|---|---|---|
| `doc` | 5 | `adjudicate_only` | 文档域唯一 LLM 点位：歧义裁决 |
| `diagram` | 9 | **`none`** | 全符号管线，构造性禁止大模型 |
| `generate` | 4 | `narrate_only` | 步骤由算法出，LLM 只写说明 |
| `graph` | 4 | **`none`** | 纯规则与统计 |

落地为代码事实（不是文档承诺）：
- `ToolSpec.scope` / `llm_permission`；`SCOPE_LLM_POLICY` 定策略
- `registry.scoped(scope)` 返回**受限视图**——跨域调用返回 `GATE_REJECTED`（实测已验证）
- `registry.audit_permissions()` 校验两条不变式：工具已归类、"策略 none 却声明 requires_llm" 即违规
- `eval/p1_acceptance.py` 的 B/C 两项把上述不变式纳入**一键验收**

> 数量参考：单执行体工具面经验上限 ≤10–12（仅影响 ReAct 兜底路径）；本方案最大作用域 9，天然合规。
> 另：**对外不是 22 个工具**——方案 §7.4 要求"对外仅暴露只读工具"，`external_tools()` 三重收窄
> （白名单 ∩ readonly ∩ implemented）后对外 10 个，实测无写工具泄露。

**⚠ 与方案的偏差（实测发现，已修正指标口径）**：

原验收写「真值推演在合成图上的正确率 ≥95%（对 `synth_gen.truth()` 地面真值）」。
**实测 `synth_gen.truth()` 只返回结构与不变式（`{nodes, wires, invariants}`），
并没有逐激励的期望输出表** —— 该指标按原文不可实现。

已改为对**手工编制的基准真值表**校验（与被测代码相互独立）：
AND/OR/NOT/XOR/VOTE_KN(2oo3) 的 2ⁿ 全枚举逐格比对、AND→NOT 组合级联人工推演、
以及 **XOR(1,1)=0 判别用例**（若引擎把 XOR 误当 OR 会得 1，立即暴露）。
合成回归继续沿用 `roundtrip.py` 的**结构同构闸门**（node/edge recall ≥0.90）。

**本轮修掉的五类真实缺陷**（多为静默类，靠验收分项统计才发现）：
1. IR 的 `block_xy` 是 JSON list，作 dict 键直接 `TypeError`
2. 纯代数环没有汇点，若先找输出会误报"无输出节点"而**掩盖代数环**（已改为先检环）

**关键设计落地**：
- **标准路径零模型规划**：命中剧本即查表执行；参数缺失只会"反问"，绝不触发 LLM 猜测。

  LLM 规划引用不存在的工具会在**规划期**被拦截（防幻觉），LLM 不可用则明确拒绝而非硬猜。

- **熔断器**：降级率超阈值即停止产出（J 项用合成用例验证）。

**本轮修掉的四类真实缺陷**：
1. **统一配置层没承接 `.env`**：legacy 的 LLM 密钥只在其子进程生效，NIVA 主进程读不到
   → 编排层"LLM 不可用"。已在 `config.py` 补 `.env` 装载（NIVA 根 > doc legacy > diagram legacy，不覆盖已有变量）。

          │                              ├─► P4 ─► P5 ─► P6
