## 3. 本阶段的核心设计决策

### 3.1 智能体形态：单编排器 + 工具作用域（否决"一个执行体挂 22 个工具"）

docx 写"四个专业子智能体"，架构方案写"单智能体 + 工具集"，**二者说的是两件不同的事**：

| 概念 | 选择 |
|---|---|
| 运行时形态（进程 / LLM 上下文 / 留痕） | **一个** |
| 角色与权限域 | **四个**（硬约束） |

**为什么 22 个工具不是负载**：标准路径由剧本查表 + 确定性 Router 选工具，**不经 LLM**——
那条路上没有模型在做选择，工具多寡不影响选准率。上下文成本只发生在 ReAct 兜底与说明生成两个点位。

**真正的风险是确定性边界失守**：方案要求图纸理解与校验复核两个角色"不可调用大模型"。
合并为单一执行体后，这个约束只能写在提示词里——而提示词约束不是工程约束。

**落地为代码事实**：

| 机制 | 说明 | 验证 |
|---|---|---|
| `ToolSpec.scope` / `llm_permission` | 每个工具显式声明所属作用域与 LLM 权限 | 自检枚举 |
| `SCOPE_LLM_POLICY` | 作用域级策略：`doc=adjudicate_only`、`diagram=none`、`generate=narrate_only`、`graph=none` | B 项断言 |
| `registry.scoped(scope)` | 返回**受限视图**；跨域调用返回 `GATE_REJECTED`，**工具根本不在可视范围内** | C 项实测 |
| `registry.audit_permissions()` | 校验两条不变式：①工具已归类；②"策略 none 却声明 requires_llm"即违规 | B 项实测 |
| 依赖注入层禁止 | 未授权执行体的构造函数**不接收** `llm_provider` 句柄 | 构造签名 |

### 3.2 对外只读收窄：三重过滤，可程序校验

方案 §7.4 要求"对外部智能体仅暴露只读工具，生成类工具不对外开放"。
`external_tools()` = **白名单 ∩ readonly ∩ implemented** 三重收窄，结果 10 个：

```
get_meta / list_pages / get_page / search_node / get_node /
trace_path / get_llm_view / query_knowledge / get_segments / parse_requirement_doc
```

只读模式下：写工具不出现在 `tools/list`（G 项实测无泄露），
显式调用返回 `GATE_REJECTED`（G 项实测），只读工具正常可用。

### 3.3 适配器形态：子进程 + 制品仓

两个 legacy 工程都存在顶层同名模块（`config.py` 等），且内部一律绝对导入。
同进程挂 `sys.path` 存在遮蔽风险。因此采用**子进程 + 制品仓**：

- `adapters/*/legacy` 的真实计算在 `_runner.py` 子进程里执行，`cwd=<legacy 根>`
- 结果经制品仓 JSON 往返，legacy 的 stdout 日志由调用方收集为 warning
- **legacy 崩溃不会拖垮智能体进程**（"能力可失效、降级必可见"）
- 每次调用都是干净解释器，不残留跨调用状态 —— 顺带强化可复现性

| 制品 | 位置 |
|---|---|
| 矩阵快照 | `artifacts/matrices/<matrix_id>.json` |
| 追溯矩阵 Excel | `artifacts/exports/<matrix_id>.xlsx` |
| 子进程 RPC 中转 | `artifacts/rpc/{doc,diagram}/` |

`matrix_id` 由输入**确定性派生**（`sha256(kind|mode|inputs)`），同输入必同 id —— 天然幂等且可复现。

### 4.3 过程中修掉的两个真实缺陷

| 缺陷 | 症状 | 修复 |
|---|---|---|
| IR 边用**标签**引用端点（`IM#1`→`R`），而节点 id 是 `n017` | 修复前 9 页 **291 条信号流边全部被静默丢弃**（只剩 contains） | 端点索引同时按 id 与 label 建；修复后 291 条 `flows_to` 全部恢复 |
| 验收脚本读错字段（`rows` vs `paths`） | `trace_path` 明明返回 13 条路径却报 0 | 修正断言 |

> 第一条是典型**静默降级**——没有报错，只是边少了。它之所以被发现，是因为验收脚本
> 统计了"按关系分组的边数"而不只看总数。这正是"验收必须看分项、不能只看总分"的原因。
