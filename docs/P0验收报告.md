## 6. ⚠ R1 风险闸门：结论与它带来的计划变更

这是 P0 最重要的产出，**它推翻了方案原有的一项核心假定**。

### 6.1 结果

在真实 9 页 SAMA 图纸 IR + 5 份真实核电厂文档（共 30 页）上：

| 锚点                                     | 命中率                                      |
| -------------------------------------- | ---------------------------------------- |
| **A1 位号**（MP101 / 401XU1 / YTSM007MP…） | **0 / 66 = 0.0%** ❌                      |
| A2 图名/系统号/图号                           | 0 / 12 = 0.0% ❌                          |
| **A2b 系统代号 / 中文系统名**                   | **3 / 10 = 30.0%** ✅（CAM / TSA / TSM）    |
| A3 回路号 / 跨页引用                          | 1 / 66 = 1.5% ❌                          |
| **A4 功能叙述关键词**                         | **3 / 13 = 23.1%** ✅（BUP / DAS / 蒸汽管道隔离） |

### 6.2 我是如何确认这不是提取故障的

第一版脚本直接给出 0%，这是"方案地基被推翻"级别的结论，不能贸然接受。逐层排查：

1. **文本层是否完好？** 是。5 份 PDF 均为矢量文本（图像块仅系统需求有 49 个小图，非扫描件），  
   正文可正常提取，无乱码（如"3.2.2.1 F-SC1 级要求"完整可读）→ **排除 OCR/提取问题**。
2. **是否只是标签形式不同？** 检查语料中所有"位号样式令牌"：命中的全是  
   **标准号**（HAD102、GB/T12727、IEEE1012、ISO9001）与**需求条目号**（SYRS001–014、ICADS001–…、FZSDCS34），  
   **没有任何仪表位号** → 确认是抽象层级差异，不是形式差异。
3. **是否两个项目本就不同系统？** 不是。文档中确实出现  
   `6  CAM  安全壳大气监测系统`（DCS需求说明书缩略语表），而图纸图签为  
   `图名=CAM101MP安全壳大气压力`、`系统号=YCAM` → **同一系统族**，说明关联客观存在，只是**粒度在系统级而非位号级**。

### 6.3 根因

需求/设计文档处于**功能与系统抽象层**，它们引用标准、条目号与系统名；  
**位号只存在于 IO 清单与定值手册**，那是图纸域内部与知识层的词汇。  
原方案把位号当作"唯一现实锚点"，在"需求文档 ↔ 图纸"这一跨层级上不成立。

### 6.4 已写入计划的修正

- **主锚点**：A1 位号 → **A2b 系统代号 + A4 功能语义**；位号降级为"图纸域内部与 IO/定值知识层专用"。
- **演示话术必须改**：不可承诺"点位号级精确联动"，改为"系统/功能级关联 + 证据与置信度可见"。
- **P2 增设前置 Gate**：现语料中 `系统需求/DCS需求说明书.pdf` 仅为 **15 页摘录（文档自述 8/90）**，  
  且**缺失 SAMA/FD 设计图本身**（只有 1 份组态样图）。因此上述比率**系统性偏低，不可外推**；  
  取得完整文档与同项目设计图后必须**重跑 R1 复测**，再最终裁定 P2 路线。

详见 `docs/实施计划.md` §4。

1. **类名真实性校验**：用例库最容易犯的错是臆造类名（方案原文举例用了 `COMPARATOR`，

   必须指向真值推演；若出现具体数值则告警。这守住了"期望值不是 LLM 编的"这条底线。
